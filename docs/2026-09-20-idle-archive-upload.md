# 演示版：录音结束后补传

## 无卡兼容修正

启动时没有存储路径，或本地归档初始化/目录/manifest 写入失败时，允许已授权任务以纯实时模式启动，屏幕显示“无本地保存”。注册失败、任务目录已存在等非存储不可用情形仍拒绝启动，不以降级绕过任务校验。无卡时只有既有有界内存重传，不能承诺断网完整录音。

归档读取根目录失败或发现存储不可用后，暂停后台反复扫描；下一次 Begin 重新尝试目录创建。此变更不提供自动热插拔重新挂载，重新插卡仍可能需要存储检测或重启。中途写卡失败仍明确中止任务，屏幕提示存储异常，不伪称本地完整。卡内旧文件不清除。

本版替代录音期间自动补传的调度策略。挂载 TF 卡且任务登记成功后，每次录音持续写卡，同时维持实时音频上传和转写。断联或实时缓存满时保留原有异常标记和本地采集；重连恢复实时输入，历史卡内音频在录音结束后处理。

补传 HTTP 回调逐请求检查 recording 和 tail_pending；任一为真就暂缓全部归档 HTTP 请求，包括旧任务。新任务启动阶段暂停二进制补传，保留开始采集前必要的小型任务登记。录音停止、实时尾包处理结束且设备联网后，已有扫描器自动继续上报、上传、校验与完成确认。

已经发出的 HTTP 请求不跨线程强行取消，可能与新录音开始短暂重叠；现有发送预算为 3 秒，此数值不是整个 HTTP 请求的严格总耗时保证。此次不扩大音频内存缓存，也不修改 ACK 超时。

继续保留分段持久化确认后的本地删除规则。实时 ACK 不能作为 TF 删除依据。本版正常任务也走已有归档确认流程，尚未实现通过实时文件完整性证明免除归档上传。补传不自动补转写。

录音期间不进行归档 HTTP 上报，因此服务端卡内数量和归档采集进度可能停留在开始时；界面须明确这是上次上报值，结束后更新。

真机验收：正常录音；断网后持续录音、重连恢复实时转写；离线结束后联网补传；旧任务补传期间开始新录音。每项检查完整文件采样数、分段哈希、实时缺口和本地待传字节，不以编译通过代替验收。
