# P4 双路 HX711 称重功能

适用板型：Waveshare ESP32-P4 WiFi6 Dev Kit B，小智分支
`codex/p4-wifi6-dev-kit-b-screen`。两路各用一个 HX711 模块和一个 750g 称重传感器，
独立去皮、校准和状态，不能直接把两路数值当作一个 1500g 秤。

## 工作项状态与硬件数量

对应工作项“传感器调试”：读取原始数据、去皮、已知重量标定、检查波动和偏载；
完成标准为空载归零、同一物体多次称重结果稳定、误差达到目标。

当前状态：**软件基础功能已实现，等待传感器到货联调，尚未完成实物验收。**

一个独立称重台使用一个 HX711 加一个称重传感器即可，第二路保持关闭。
两个分别称重的托盘才需要两套；现有软件支持一路或两路独立启用。
暂按单台先联调、另一套备用的建议准备，最终安装数量尚未确认。
两个传感器共同支撑同一托盘不属于本次独立双路实现，需要另行设计机械安装和合成标定。
750g 是所购传感器的标称量程，承载评估应包括托盘与物品，去皮不会增加物理承载能力。

## 当前实现

- 板级模块 `board_scale.*`，沿用现有物理串口命令入口。
- 每次启动两路均关闭，不创建采集任务，不初始化任何称重 GPIO。
- 首次启用后独立低优先级任务轮询；不等待转换，不阻塞音频和主事件循环。
- 模拟和真实读数经过同一个 `ScaleState`，10Hz 处理，8 个样本、至少 700ms、
  窗口峰峰值不超过 1g 才判定稳定。阈值是待硬件验证的初值。
- 稳定重量达到 5g 触发 `placed`，回到 ±2g 触发 `removed`，连续相同状态不重复触发。
  首次稳定、去皮后、校准后、重连后仅建立基线，不追补无法确认的事件。
- 数据超过 1.5 秒未更新则失效；ADC 饱和或绝对重量超过 750g 标为过载。
- 未校准时只提供原始读数，不把原始 ADC 数字当成克数。
- `GetBoardScaleStatus(0/1)` 提供线程安全快照，包括模式、连接、校准、稳定、过载、
  克数、原始读数、时间戳和事件序号。读取克数前必须检查连接、校准和过载状态；
  要执行重量相关业务，还需检查稳定状态。模拟模式有显式标记。

本次提供采集与处理、串口联调接口。事件目前写入设备日志；尚未接屏幕、云端上报、
自动录音或语音播报，避免在业务触发条件未确定时自动操作。事件序号供后续消费者去重，
快照只保留最近事件，不是保证每条送达的事件队列。

## 没有硬件时验证

用现有设备串口入口发送以下命令，每次修改重量后等待约 1 秒：

```text
p4 scale 1 sim
p4 scale 1 status
p4 scale 1 weight 100
p4 scale 1 status
p4 scale 1 weight 0
p4 scale 1 status
p4 scale 1 disconnect
p4 scale 1 reconnect
p4 scale 2 sim
p4 scale 2 weight 800
p4 scale 2 status
p4 scale 1 off
p4 scale 2 off
```

启用模拟后先等待空秤稳定，再放入模拟物品，日志应分别出现一次 placed/removed。
第二路 800g 应显示 overload=1、stable=0。模拟 `weight` 接受 -1500 到 1500g，
这是用于测试异常的模拟范围，不是传感器可承载范围。断线后克数可能保留上一读数，
但 connected/valid 为 0，不应继续使用。`tare` 对模拟模式同样有效；weight 是去皮前
的模拟负载，因此去皮 100g 后输入 100g 应显示 0g。

## 硬件到货后

1. 对照实际板卡版本和已占用引脚，确认两组空闲 DOUT/SCK。
   `hx711_config.h` 默认均为 -1，未配置时 `hardware` 返回 rejected。
   不改动现有板卡音频、USB、屏幕、TF、C6 或以太网引脚；软件检查 GPIO 有效性和
   两路相互冲突，但不能替代原理图及实际接线审查。
2. 核对模块供电及 GPIO 电平兼容性、共地和传感器 E+/E-/A+/A-，不要只凭线色接线。
3. 配置并重新编译后执行 `p4 scale 1 hardware`。未校准时 grams 无效。
4. 空秤静置，执行 `p4 scale 1 tare`，确认 result=ok。
5. 放上已知重量（支持 1–750g，例如 100g），稳定后执行 `p4 scale 1 calibrate 100`。
6. 分别测试空载、多个参考重量、放入/取走、断线、录音并发。另一通道重复操作。

校准前的原始稳定门槛是 8 点峰峰值不超过 1000 ADC counts，需要按真实噪声调整。
支持桥路极性相反产生的负校准系数。去皮和校准仅在本次运行有效，切换模式或重启
后必须重做；模拟参数不会保存到真实校准。精度、量程边缘、时钟波形、机械安装和
录音并发均需要实物验证，软件测试不能证明物理精度。

读取时序依据 [AVIA HX711 数据手册](https://datasheet.lcsc.com/lcsc/Avia-Semicon-Xiamen-HX711_C43656.pdf)：
24 位有符号数据，25 个时钟选择 A 通道 128 倍增益，短临界区保护时钟高电平。

## 自动验证

`python -m unittest discover -s scripts/tests -v` 包含编译期 C++ 行为断言：
24 位符号扩展、稳定延时、毛刺、抖动、事件去重/回差、过载、去皮、反极性校准、
断线/重连及通道隔离。需要 CXX、clang++ 或 g++。

Windows 沿用本地已配置的 P4 构建时，在 ESP-IDF 环境中执行：

```text
idf.py -DCMAKE_NINJA_FORCE_RESPONSE_FILE=ON reconfigure build
```

新增板级 `.cc` 由 CMake glob 收集，需要 reconfigure。响应文件选项用于避免此项目
在 Windows 上出现编译命令行过长。此命令使用现有 sdkconfig，不选择其他板型或烧录。
