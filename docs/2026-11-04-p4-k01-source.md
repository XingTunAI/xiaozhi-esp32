# P4 K01 四麦音源接入

日期：2026-11-04。状态：2026-11-11 已用 IDF 6.1 编译上板，K01 MIC1 经听见完成第一段 60 秒静音录音（见文末）。

## 做了什么

把星豚自研声卡核心板 K01（ES7210 四通道 ADC，经 FFC 接 L-401 线阵或 C-401 环阵）作为第三种录音音源，与 USB 声卡、本机双麦 PDM 并列。上传、ACK、断线补传、TF 归档、录音授权全部沿用现有 Voice Lab 链路，没有新增传输逻辑。

- 接线、引脚选择和首次上电记录：voice-lab 仓库 `docs/tech/ESP32-P4-WIFI6-DEV-KIT/K01-AUDIO-BOARD-WIRING.md`。
- 引脚、I2S 格式和 ES7210 配置，照搬 2026-11-04 已在同一块板上通过的探针（voice-lab `firmware/p4-k01-probe`）。该探针的验证结果：I2C 只见 0x18/0x40，芯片 ID 正确，8 秒 TDM4 采集零错误。

| 项目 | 取值 |
|---|---|
| K01 I2C | I2C0，SDA GPIO26，SCL GPIO27；不用板载 I2C1，因为板载 ES8311 也是 0x18，会冲突 |
| 采集 | I2S2 TDM RX 主机，MCLK 20 / BCLK 21 / WS 23 / DIN 22；16 kHz，4 槽 × 16 bit；MCLK 256fs |
| 端口分工 | I2S0 = 本机 PDM，I2S1 = 板载 ES8311 播放，I2S2 = K01，三者互不抢占 |
| 输出 | 16 kHz 单声道 PCM16，每帧 20 ms，与 PDM/USB 相同 |
| 处理 | 只有原始数据：可选单颗麦，或四颗麦直接求平均。不做 AFE、AGC，也不加数字增益 |
| 播放 | 仍由板载 ES8311 播放提示音；K01 板上的 ES8311 和功放本版不使用（AMP_EN 由板上下拉保持关闭） |

ES7210 的 TDM 槽位顺序是 MIC1、MIC3、MIC2、MIC4（见 `box_audio_codec.cc`），代码按物理麦号选槽。2026-11-12 已在 C-401 上逐颗核实（PGA 0 dB 对麦孔吹气，被吹那一路比其他三路高 19–33 dB），映射正确，记录见 voice-lab 文档 `D:\projects\voice-lab\docs\tech\ESP32-P4-WIFI6-DEV-KIT\K01-AUDIO-BOARD-WIRING.md`。

## 无屏运行（2026-11-11）

7 寸屏改为可选：开机时探测屏幕控制器 0x45，探测不到就以无屏方式运行（`Screen controller 0x45 not found; running headless`），使用基类的 NoDisplay；网络、听见连接和录音全部照常。需要屏幕的串口命令（`p4 employee`、`p4 account-page`、`p4 binding-button`、`p4 record-button`、`p4 ui-freeze/resume`）在无屏时只打印提示，不会崩溃。无屏时录音由听见管理端远程开启。接屏时行为与原版一致。

## K01 与 H2 USB 口互斥（2026-11-11）

双 USB Host 版为了让 FS OTG 走 H2（GPIO24/25），开机时调用 `usb_wrap_ll_phy_select(&USB_WRAP, 0)`，USB Serial/JTAG 随之改走 FSLS PHY 1，也就是 **GPIO26/27**，正好是 K01 的 I2C 脚。探针固件不装 USB Host，所以 11-04、11-11 的探针都正常；换到听见固件后，K01 在 0x40 探测超时，录音开始约 2 秒就以 `failed_to_start_recording` 结束（11-11 22:37 两次）。

修正：USB 布局在开机时按 NVS `p4_audio/source` 决定，并保持到下次重启。

| 开机时音源 | USB 布局 |
|---|---|
| K01 | 只装 HS USB-A（`peripheral_map = BIT0`），不切 PHY；USB Serial/JTAG 留在 GPIO24/25，GPIO26/27 给 K01 I2C。H2 口不可用 |
| USB / PDM | 与原版一致：HS USB-A + FS H2 |

开机日志分别为 `USB host: HS USB-A only; FS H2 off because K01 uses GPIO26/27` 和 `USB dual host: HS USB-A + FS H2 (GPIO24 D-, GPIO25 D+)`。用串口在 K01 与 USB/PDM 之间切换时，如果需要换布局，固件保存设置后打印 `USB layout must change ...; restarting in 1 s` 并自动重启；配对凭据和 Wi-Fi 都在 NVS，重启后自动重连听见。

## 选择与命令

选择保存在 NVS `p4_audio`，**从下一段录音开始生效**，不会在录音中途换源；音源初始化失败时报错，不会悄悄改用别的音源。

| 串口命令 | 作用 |
|---|---|
| `p4 audio k01` | 下一段录音使用 K01（通道和增益沿用上次设置） |
| `p4 audio k01 mic 1`…`4` | 只录这一颗麦，同时选中 K01 |
| `p4 audio k01 mean` | 四颗麦求平均，同时选中 K01 |
| `p4 audio k01 gain 30` | ES7210 PGA 设为 30 dB（0–37.5，可带一位小数），不切换音源 |
| `p4 audio usb` / `p4 audio pdm` | 切回原有音源 |
| `p4 audio status` | 显示下一段录音的音源、PDM 增益、K01 通道和增益 |

新键 `p4_audio/source`：0 = USB，1 = PDM，2 = K01；另有 `k01_mode`（0 = 平均，1–4 = 单颗麦，默认 1）和 `k01_gain`（单位 0.1 dB，默认 300）。旧键 `pdm` 继续同步写入。回滚到旧固件时，K01 会被当作 USB，不会误开 PDM。外设页“下次录音”一行会显示 `K01 MIC1` 这类 ASCII 文字，不需要重新生成字库。

开录时打印 `K01 capture started: ... PGA x dB (REG43-46=..)`，回读的低 4 位是实际增益档（0 = 0 dB … 10 = 30 dB，14 = 37.5 dB），高位 `0x10` 是该路使能。录音期间，每秒打印一行 `P4K01`：四颗麦各自的均方值和峰值、读错误数、DMA 溢出数，用来做逐颗轻敲测试和排查故障。

设备上报的 `audioFrontend` 改为 `p4-usb-pdm-k01-selectable`，`audioFrontendFirmware` 为 `p4-mm-afe-usb-k01raw-v2`（v2 起支持四路原始上传）。它们只表示设备支持哪些组合，不代表某一段录音实际用了哪个音源；实际音源要看日志里的 `K01 capture started` 和 `Next recording input`。

## 四路原始麦上传（2026-11-12）

为了在服务端/电脑上用同一批录音试波束形成、降噪等软 DSP，K01 可以把四颗麦的原始声音一起上传到听见。由管理端决定，设备不能自己切换。

- 能力上报：开机时音源为 K01，hello 的 `controlCapabilities` 多一项 `four-mic-evidence`。
- 采集计划：管理端勾选“保存四路原始麦”后，`desired_config.capturePlan` 为 `strategy=four_mic_evidence`、`transport.channels=4`、`layout=k01_mic_1_4`。固件只认这一种多声道计划；其他多声道计划，或当前音源不是 K01，`config_ack` 返回 `unsupported_capture_plan`，不会回落成单声道却报告成功。
- 数据：VLA2 头 `channels=4`、`flags=0x04`，PCM 按物理 MIC1、MIC2、MIC3、MIC4 交织（固件已按 `kMicToSlot` 从 TDM 槽位重排）。每包仍最多 25 个 20 ms 帧，即 64,000 字节 PCM，仍在 64 KiB 上限内。序号、样本号、ACK 窗口都按“每声道样本”计，与单声道语义一致。ASR 用哪一路由服务端按管理端选择决定。
- 通路：K01 采集在录音边界（`ResetInputCapture`）锁定声道数；AudioService 把编解码器给出的交织数据原样交给 Voice Lab 客户端，单声道录音仍取第 0 路（与原来行为相同）。录音结束后声道数复位为 1，不影响唤醒词等其他用途。
- 缓存：仍是 12 秒时长预算，四路占 PSRAM 约 1.5 MB。上行持续跟不上时，缓存满就明确结束录音并报错，不会静默丢帧。
- 限制：四路录音不写 TF 卡归档（归档和补传接口是单声道的）。带宽是单路的 4 倍，约 1 Mbit/s。2026-11-12 早上办公室上行慢，单路都在约 25 秒内把 12 秒缓存耗尽（`Voice Lab PCM buffer full; rejecting capture chunk`，见 voice-lab 接线文档）。四路录音要先确认上行带宽。

## 弱网：缓存加长与测试热点优先（2026-11-13，固件标识 `p4-mm-afe-usb-k01raw-v3`）

现象：11-13 上午在 Rex 工位四路连录 20 分钟零缺口；下午换到风扇旁的测试位置后，四路三次都在 19–20 秒自停，单路 MIC1 也只传上约 9 秒就断（29.5 秒自停）；搬回工位（RSSI −48）四路传了 49 秒后同样自停。服务端日志显示媒体 WebSocket 反复被接受，但没有音频继续到达，控制通道始终在线。管理端审计里的 `admin_recording_stop_requested` 是设备自报 `finalizationState=pending` 后由服务端补记的（voice-lab `src/voice_lab/api.py` 中 `begin_admin_stop(send=False)`），不是有人点了结束按钮。

改动只调参数和选网，保持既有机制不变：

- **有界缓存加长**：`kPendingPcmBudgetSeconds = {120, 60, 30, 12}`，开录时从长到短尝试分配 PSRAM（4 路 120 s 为 15.4 MB），12 s 为下限，日志打印 `Voice Lab PCM backlog budget`。缓存满后的行为不变：无 TF 卡时仍显式结束录音，不静默丢音。XIAO ESP32-S3 基线是 30 s PSRAM 队列；P4 的 PSRAM 更大且四路码率是单路的四倍，所以放宽到 120 s，并保留 30 s 和 12 s 作为回退档。这只能扛住短时断网，扛不住长期带宽不足。
- **多 Wi-Fi 选网**：照搬 `voice-lab-quality/firmware/xiao-esp32s3-respeaker` 的 `connect_wifi`：先扫描，按 RSSI 顺序尝试已保存的网络，再尝试扫描里没看到的已保存网络（隐藏 SSID）；断网 15 秒后重新选网。新增一条（Rex 定）：`voicelab-test` 只要可见就最先尝试；设备空闲且连在别的网络上时，每分钟扫一次，看到它就切过去。录音期间不扫描、不切网。
- **保存热点**：串口命令 `p4 wifi save <ssid> <password>` 只保存、不连接，日志只打印 SSID 和密码长度；`p4 wifi list` 列出已保存的 SSID。热点凭据存放位置：`D:\private_keys\xingtun\voicelab-test-hotspot.md`，不进 Git。
