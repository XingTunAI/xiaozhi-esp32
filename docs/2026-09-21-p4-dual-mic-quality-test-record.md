# P4 双 PDM 麦克风音质测试记录：未达标，暂停调参

记录时间：2026-09-21 15:06（北京时间）。用户要求先记录，本轮停止继续调参和主动试录。

**后续决定：暂不支持双麦，使用USB声卡。** 已通过设备串口执行 `p4 audio usb` 并回读确认，选择保存至NVS。按用户要求移除外设页双麦/USB切换、L/R、AFE和增益按钮及对应UI动作，保留SD检测和只读音源状态。双麦源码和历史记录保留作排查资料；下文R×4等配置均是本轮历史测试状态，不再是当前使用选择。

## 结论与用户反馈

**当前双麦音质未达标，不能按可用功能验收。** 采集、上传、文件保存或编译测试通过，不代表人声清楚或转写完整。

- 用户实际多在贴近至约10cm范围内，手持麦板正对自己讲话；此前反复提示的“30cm”是测试建议/话术，不是已验证的实际距离。
- 用户反馈：正常人声很弱；尖峰、电流声和沙沙声明显；原始 L/R 勉强，AFE 更差；很多时候感觉没有录进去。
- “没有录进去”尚未最终区分为完整录音缺少可辨识人声、VAD 未送出、或 ASR 没有识别。不能仅凭样本数量完整否定用户反馈。
- 麦板由杜邦线连接 GPIO2/3，旧资料标记 CLK=GPIO2、DAT=GPIO3、3V3/GND。这一路是 PDM，不经过 ES8311 的模拟输入增益。线长、接触质量、麦克风芯片具体型号及实际拾音孔朝向尚未现场核实；不能认定杜邦线是根因。

## 用户补充的麦板照片

用户后续提供正面照片，可见细长PCB标记 `DUAL DMIC`，两端分别为 `L / M1` 和 `R / M2`，连线标注 `6cm`。两颗金属封装表面各有一个可见小孔；照片这一面未见独立的大型DSP/codec芯片。中央边缘可见一组焊点，左侧有一列焊盘。不能仅凭外观判定焊点虚焊或短路。

麦壳字符无法可靠辨认，未确定芯片型号；背面、VDD/GND/CLK/DAT针序、去耦元件及完整转接线不可见，不能判定板上没有外围元件。`DUAL DMIC`说明数字双麦标识，但PDM接口判断仍结合此前模式九资料和GPIO2/3接线记录，不由丝印单独证明。丝印L/R与固件slot0/slot1的对应尚未标定，固件PDM R不等于已证实正在读取照片右侧M2。

本次仅补充记录，未修改固件或重启试录。

用户进一步明确：**麦板上只有两颗麦克风，没有其他物料。** 以用户对实物的确认更新外围器件情况：板上没有独立DSP/codec，也没有外置电阻、电容。此前“无法从正面照片判断背面外围元件”的表述仅描述照片本身的证据限制，不再作为待用户确认的问题。麦克风封装内部电路、具体型号和母板侧供电去耦仍未知。没有麦板就近外置去耦是后续核对电源完整性的线索，不足以认定为噪声或弱人声的根因；暂停状态保持。

## 原始探针对比结论

详细对比见 [配置差异记录](2026-09-21-pdm-probe-config-comparison.md)。

- 2026-09-14 P0对应 `voice-lab/firmware/p4-voice-terminal/main/probe.c`，不是后来带AFE的 `audio.c`。旧试验记录有人声录音、两路非复制和电平变化，但没有清晰度/ASR准确率验收。
- P0每次启动先读掉约200ms预热，8秒音频写PSRAM，停止后再经UART传输；没有网络、SD、UI、播放和AFE。
- GPIO、16kHz PCM16双声道格式、DSR_8S、35.5Hz高通和硬件增益×1等默认配置一致。核对官方IDF5.5.4和本机6.1未发现默认PDM增益变小；驱动实现仍有差异，未完成实际时钟波形测量。
- 旧WAV和冻结构建目录 `voice-lab/var/p4-probe/` 在本机没有找到，不能声称已回听旧音频。
- 原始模式补回预热后，后两条已观察到的录音没有复现开头满幅瞬态；这是局部改善，不说明人声弱和全部中途噪声已解决。

## AFE 与其他未解决问题

- 当前实际AFE日志为 `[input] -> |SE(BSS)| -> [output]`。代码设置NS开关不证明额外降噪模块实际运行。不能再称“已验证双麦增强”。
- 移植参考业务源码加载模型且开启VAD/WakeNet、内部RAM feed buffer；当前模型nullptr、VAD/WakeNet关闭、vector feed buffer，版本也不同。尚未做同一输入的同步原始双声道/AFE输出对照，不能指定某项就是根因。
- 用户报告启动约7秒等待：代码确实先授权、连接、提示，再开启采集；尚未优化启动体验。
- 用户报告停止时重启：一次读到软件重启原因码3，没有抓到对应触发调用栈；后续未复现，不能记为修复。
- TF卡恢复日志 `SD recovery finished: ESP_OK`；其后有正常录音。但早先失败任务仍有归档HTTP超时重试，未彻底处理。
- 网络ACK超时及重连仍出现；SD备份完整与实时ASR完整需分别检查。

## 后续恢复工作时的顺序

1. 先确认用户指的是完整录音缺少可辨识人声，还是只有转写缺失；不要用“保存完整”替代听辨证据。
2. 保持固定麦板、实际距离和背景条件，保存同一次左右原始音频；必要时录下参考声音，避免无限要求重复同类短录音。
3. 对中途噪声检查接触、供电/时钟波形及外设活动相关性。未证实之前，不归咎杜邦线、不盲加电阻或改供电。
4. 输入稳定后，按语音片段电平调增益/限幅或AGC；单纯数字放大不能改善信噪比。
5. 最后做AFE单变量对照，校验模型、通道、缓冲与版本；明确清晰度和转写效果通过后才能验收。
