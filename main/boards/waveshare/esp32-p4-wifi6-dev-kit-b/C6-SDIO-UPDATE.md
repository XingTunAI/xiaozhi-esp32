# C6 免焊线升级

日期：2026-09-17。P4 主机 ESP-Hosted 版本 2.12.12。

## 实现

物理串口命令 `p4 c6-update http://<维护电脑>:<端口>/<sha256>.bin` 将 C6 应用完整下载到 P4 PSRAM，校验 SHA-256、芯片类型及 `network_adapter` 项目名后，调用 ESP-Hosted 的从机 OTA begin/write/end/activate。不写 P4 分区表，不覆盖设备凭据。维护下载必须连接以太网，通过 `esp_http_client` 的 `if_name` 绑定 `ETH_DEF`，避免同网段 Wi-Fi 路由抢占。

仅在设备停止录音时执行。维护期间保持供电，不启动录音。维护期间用 `esp_wifi_stop()` 暂停 Wi-Fi，保留 Hosted/SDIO；非重启退出自动重新启动 Wi-Fi。仅绑定网口仍观察到 HTTP 超时，暂停 Wi-Fi 后才完成实测下载。升级文件由同版本 ESP-Hosted 的 `slave` 项目以 ESP32-C6 / SDIO 配置构建。不得把此文件当作 P4 应用烧入。

begin 请求由从机选择 OTA 备用分区；接口不支持或分区不可用时停止。下载、校验失败时不调用 OTA。写入或结束失败时不调用 activate。只有重启后读回版本才能确认成功；旧固件版本查询失败输出的 0.0.0 不是实际版本。

## 本次构建

- C6 应用版本：2.12.12；大小：1,282,224 字节。
- SHA-256：`cd6965b649c896cea3021f4f8495949780c55749a67484a5144417e663e8c8e3`。
- P4 升级入口固件 SHA-256：`29c84199c4fc33a0ed0b6d3fd4e32e6384d34a58049eb0745a5297f0821958ae`，大小 4,326,416 字节。
- 主机测试：83 项通过；P4 编译通过。

此路径依赖现有 C6 固件和 SDIO 链路仍能响应，不能替代固件损坏时的 UART 恢复，也未取得旧 C6 的完整 Flash 备份。

初版未绑定接口时，HTTP 请求从 Wi-Fi 地址 192.168.5.116 发出，只收到 388,800 / 1,282,224 字节后超时；未调用 OTA begin，C6 未写入。这是改为强制网口下载的实测依据。

## 真机结果：升级成功

2026-09-17 约 11:51，经现有 P4 USB 串口部署升级入口，再由网口下载并通过板载 SDIO 完成 C6 更新，全程未接 C6 UART、未焊线。

- 43,762 ms：镜像 SHA-256、C6 芯片及应用信息校验通过。
- 44,077 ms：`SDIO OTA begin: ESP_OK`。
- 60,349 ms：写完 1,282,224 字节。
- 60,704 ms：`SDIO OTA end: ESP_OK`。
- 65,705 ms：旧固件对独立 activate 请求超时；P4 重启进一步验证。没有把此超时视为成功依据。
- 重启后 7,065 ms：`C6 firmware query: ESP_OK, version=2.12.12`，确认新镜像已启动，与 P4 主机版本匹配。
- Wi-Fi 扫描到 13 个 AP，重新取得 192.168.5.116，初次 ping 4/4 成功；延迟 412–718 ms，仍需独立长时网络测试，不宣称稳定性问题已全部解决。
- Voice Lab 控制 WebSocket 握手成功，服务器确认设备在线、合同兼容、空闲，网口地址 192.168.5.80。

完整本地日志：`local-build-backups/p4-dual-usb-20260917/c6-update.log`。其中含多次未写入的下载失败尝试，应以最后一次校验、写入、重启和版本读回组成的完整记录为准。
